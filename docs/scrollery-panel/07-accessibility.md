# Panel report — Accessibility, Inclusive Design & Localisation

## Summary
Scrollery is unusually careful about the things that are hard (blend modes, dark-ground compositing, pronoun resolution) and unusually careless about the things that are cheap (live regions, `aria-pressed`, a font fallback stack). Its accessibility failure mode is not "the UI is broken" — it is that **the composer is a purely visual instrument with no non-visual channel at all**: 7,680 reachable combinations, a preview that changes silently, a rank control whose entire state is colour, and three explanatory sentences no screen reader will ever hear. On pronouns the module is genuinely good — all 17 distinct `pronoun_freetext` values in the live DB resolve correctly, `he/him -> his` included, and the flavour text is 100% second-person, so the gendered surface area of the whole certificate is exactly one word. The two real defects: a **preview that lies about type size for long and non-Latin names** (same class as `1e19545d`, unfixed by it), and a **type family that cannot render 42 of the 155 non-ASCII personas** with no fallback declared.

## Findings

- **[BUG] The composer preview never rescales type, so long and non-Latin names print smaller than previewed**
  - Now: `_text.tpl:20-25` computes name and reason font sizes server-side from `strlen()`, baked into `style="font-size:max(1.36em, calc(2.55em + -0.374em*((N/8))))"` at `:48` and `:74`. `scrollery.js:379-409` (`applyText`) writes the typed name into `innerHTML` and **never touches the parent's `font-size`**; `reload()` only fires on award/rank/variant/recipe/pronoun change. Type a persona by hand and the preview keeps whatever size was computed when `player` was empty (largest bracket, 2.55em). Worse, `strlen()` counts BYTES: `Estēs Az-ḩkoǧak` is 15 chars / 19 bytes; `Nokren ᚨᛒᛟᛟᚹᚺᛟᚷᛟᛞ` is 17 chars / 34 bytes — accented and non-Latin personas are shrunk as if half again as long.
  - Proposal: (a) `strlen` -> `mb_strlen(...,'UTF-8')` in `_text.tpl:20-25`; (b) port the three formulas into `applyText()` and set `font-size` on `.AwardeeName`/`.Award_Reason` as the officer types — or simpler, debounce a `reload()` on `playerEl`/`reasonEl` input the way the pronoun field already does on `change`.
  - Why: the preview is what an officer trusts before committing paper. A 40-char persona previews at full size and prints overflowing the underline; every accented name prints a size smaller than it should.
  - Effort: S — Risk: JS formulas must stay literally in sync with `_text.tpl`; pin with a test the way `prettyDate` mirrors `FormatDate`.

- **[BUG] BlackChancery cannot render 42 of the 155 non-ASCII personas, and the font stack has no fallback**
  - Now: `scrollery.css:163` is `font-family:"BlackChancery";` and `:190` is `font-family:'Averia Serif Libre';` — **no fallback family on either**. Parsed the cmap: BlackChancery carries 214 glyphs, Latin-1 only. Missing: `ð þ Þ Ð Ý Đ ł Ł š ž č ř ē ī ō ā ș ş ǧ`, all Greek, all Hangul, all Elder Futhark. Against the 155 real non-ASCII personas, **42 contain at least one unrenderable character** — `Fox Helsygmaður`, `Juna Šumski`, `Nokren ᚨᛒᛟᛟᚹᚺᛟᚷᛟᛞ`, `Kenneth Gorzav Neacșu`, `Estēs Az-ḩkoǧak`. With no fallback the browser drops to the user's default font mid-word, or renders tofu.
  - Proposal: declare a real stack — `"BlackChancery","Averia Serif Libre","Times New Roman",serif`. Then run the persona against a shipped codepoint list and show one honest line: *"Some characters in this name are not in the certificate typeface and will print in a substitute font."* The data also holds mojibake (`Kolfinna EgilsdÃ³ttir`, `DrÃ¦ngr`) that prints verbatim — pre-existing, but the certificate is where a player finally sees it.
  - Why: a Knighthood scroll with the recipient's name half in blackletter and half in Times is a keepsake with a visible defect, landing disproportionately on non-Anglophone personas.
  - Effort: S (stack) / M (warning) — Risk: regenerate the codepoint list if the woff2 is re-subset; ship as a data file with a test.

- **Rank pills carry selection and award history in colour alone, with an orphaned label** — WCAG 1.4.1 and 4.1.2, fix lands on three surfaces at once
  - Now: `revised.js:12-24` (`tnRankPaint`) communicates held/forward/selected purely by CSS classes resolving to green, blue and a border. Each pill's only accessible name is `'Rank '+r` (`scrollery.js:145`). `Scrollery_create.tpl:287` is `<label for="sc-rank-pills">Rank</label>` pointing at a `<div>` — `for` on a non-labelable element, so the group has no name. The legend (`:290-293`) is two colour dots. The "click the selected pill again to clear" affordance (`scrollery.js:199-203`) exists only in a visual hint.
  - Proposal: in `tnRankPaint`, set `aria-pressed` on every pill and append `', already earned'`/`', being awarded'` to the accessible name. Wrap in `role="group"` with `aria-labelledby` and `aria-describedby="sc-rank-hint"`; drop the invalid `for`. Give the two legend keys a shape as well as a colour.
  - Why: the rank IS the certificate. A screen-reader or colourblind officer cannot tell which rank is selected or which the recipient already holds — and this same control is the grant and recommend modals.
  - Effort: S — Risk: `tnRankPaint` is shared; changing it touches Add Award and Recommend. That is the point, but needs their regression pass.

- **The composer never announces anything** — preview, error, note and count are all silent
  - Now: `#sc-stage` (`Scrollery_create.tpl:449`) is an unnamed `<svg>` whose busy state is `opacity:.45`; `mount.innerHTML = d.Html` (`scrollery.js:364`) replaces it with no announcement. `#sc-err` (`:439`) has no `role="alert"`. `#sc-recipe-note` — the only place the dark-ground and band explanations live — is set with `textContent` and never announced. In `Scrollery_bulk.tpl`, `#sc-selected-count` is the ONLY feedback when "Print selected" is pressed with more than 200 rows; with no live region the button silently does nothing.
  - Proposal: `role="alert"` on `#sc-err` and `#sc-selected-count`; `aria-live="polite"` on `#sc-recipe-note`; `aria-busy` toggled with `is-busy`; and a visually-hidden `aria-live` summary next to the stage that `reload()` fills with the composed sentence — *"Linen ground, knotwork border in Crown gold, common numerals, rank 3."*
  - Why: that one sentence is the entire non-visual channel for a tool whose output is a printed keepsake, and it costs about 15 lines.
  - Effort: S — Risk: none; derive the summary from the same option labels, not re-derived.

- **Named design presets with written descriptions**
  - Now: 12 grounds x 10 borders x 16 colour pairs x 4 numeral sets, all bare selects (`Scrollery_create.tpl:355-399`). Guidance is `$groundNotes`/`$borderNotes` (`:52-64`) covering exactly **4 of the 22** ground/border entries. `Scroll::DEFAULT_RECIPE` is the only named combination in the system; nothing can be saved or shared.
  - Proposal: a `presets` block in `scroll-recipes.php` — 8-10 curated recipes with a name and one descriptive sentence ("**Midnight** — a deep blue starfield with gold knotwork; formal, and the best of the dark grounds") — as a first control above the four pickers, with the pickers as "customise" underneath. Per-kingdom saved defaults are the natural phase 3.
  - Why: the only route by which a low-vision or blind officer can make a CONSIDERED choice rather than accepting the default; removes the "which of these 7,680 is good?" problem for everyone; directly addresses the deferred doc's real worry.
  - Effort: M — Risk: needs someone with taste to pick the ten. Reuse `NormaliseRecipe()` so a preset is just a recipe literal.

- **A computed contrast guard for grounds — and one ground that isn't a ground**
  - Now: `Scroll::DARK_GROUNDS = ['cyanotype']` (`class.Scroll.php:96`) is hand-maintained, and `.Award{color:#000000}` (`scrollery.css:165`) is flipped to white only by two hardcoded `[data-ground="cyanotype"]` rules (`:456`,`:517`). Sampled the text box of every ground and computed WCAG contrast against black type: cyanotype **1.88:1** (correctly flipped to 11.15:1 white); `forge` and `arcane` measure 4.9:1 raw but composite through their soft-light washes to **12.2:1** and **12.4:1**, so correctly NOT dark; every other ground is 11.3-15.0:1. **The list is accurate today** — but nothing keeps it right. Separately `rosewash` -> `rose/burn.jpg` (`scroll-recipes.php:32`) is 86% pure white with sparse linework and mean L 0.993 — `rose.tpl:22` uses the **`.svg`** at `multiply; opacity:0.2`, whereas the composer draws the `.jpg` as an opaque base plate, erasing the parchment entirely.
  - Proposal: a unit test that loads each `grounds` entry, applies its `GROUND_WASHES` blend, and asserts the composited text-box luminance sits on the correct side of DARK_GROUNDS membership — so adding a ground cannot silently ship 1.9:1 type. Either give `rosewash` a `GROUND_WASHES` entry matching `rose.tpl` or drop it from the vocabulary.
  - Why: the durable version of what `1e19545d` fixed by hand; and one of twelve grounds currently prints blank white paper.
  - Effort: S (rosewash) / M (guard) — Risk: needs GD/Imagick in CI, or precompute luminances into a checked-in fixture.

- **The pronoun override box has no suggestions — the datalist is dead code**
  - Now: `Scrollery_create.tpl:308-317` renders `list="sc-pronoun-list"` and the `<datalist>` only `if (is_array($Pronouns ?? null) && $Pronouns !== [])`. `Controller_Scrollery::create()` (`controller.Scrollery.php:64-71`) sets `ScopeType`, `ScopeId`, `Scope`, `Awards`, `Orders`, `page_title` — and **never `Pronouns`**. The branch is always false; the field is a bare 20-char text box labelled "Pronoun (possessive)" with placeholder "From their profile".
  - Proposal: one line — `$this->data['Pronouns'] = Model_Scrollery::possessive_suggestions();` backed by the 12 `ork_pronoun.possessive` values (`his, her, their, eir, pers, vis, xyr, hir, aer, faer`), de-duplicated. Also fix the asymmetry underneath: `possessive_pronoun()` (`model.Scrollery.php:863-874`) falls straight to `'their'` when `PossessiveFromFreetext` misses, while `ResolvePronounOverride` (`class.Scroll.php:684-689`) has a post-slash fallback — so `ze/zir` on a PROFILE silently becomes "their", but the same string typed by an officer becomes "zir". Neither matches `she / her` or `He/Him.` — `PossessiveFromFreetext` requires an exact match or a bare `subject/` prefix (`class.Scroll.php:628`).
  - Why: the override exists precisely so a player's pronoun is right on their keepsake; a blank box with no vocabulary is a feature nobody will use correctly.
  - Effort: S — Risk: none. Normalise whitespace and trailing punctuation before matching; cover in `ScrollPronounTest`.

- **Mobile stacked tables lose every column header** — `mine` and `bulk` both
  - Now: `Scrollery_mine.tpl:35-40` and `Scrollery_bulk.tpl:69-74` both do `@media (max-width:640px){.sc-table thead{display:none} .sc-table td{display:block}}` with NO `td::before` labels and no `data-label`. On a phone a row reads "Order of the Lion / 3 / 13th May 2024 / Sir Bob" with nothing saying which is which — and `display:none` on `thead` removes headers from the accessibility tree too, so a screen reader on a narrow viewport gets the same undifferentiated list.
  - Proposal: the standard `data-label` + `td::before{content:attr(data-label)}` pattern, which fixes visual and AT reading in one go. This is a two-page copy of the same block — it belongs in `reports.css` beside `.rp-*`.
  - Why: the bulk table is where an officer confirms WHO IS GETTING WHAT before committing 200 pages of card stock.
  - Effort: S — Risk: none; shared sheet, not a third copy.

- **[BUG] The denied page loses its heading reset in both themes** — the exact `orkui.css` `h1..h6` trap the project rule names
  - Now: `Scrollery_denied.tpl:8` loads ONLY `revised.css`. Its `<h1>Scrollery</h1>` at `:10` sits inside `.adm-page-header`, and the reset for that selector — including the `html[data-theme="dark"]` half — lives in `scrollery.css:75-87`, which this page never loads. `revised.css` has no `.adm-page-header h1` rule. So the permission-denied page renders the global grey `#eee`/`#ccc` pill in light mode and the `#374151` pill in dark.
  - Proposal: either link `scrollery.css` on the denied page, or move the `.adm-page-header h1` reset into `revised.css` where `.adm-page-header` itself is defined (`revised.css:6488`) — the second is correct, since `.adm-page-header` is a shared primitive and any other consumer has the same latent bug.
  - Effort: S — Risk: moving the reset changes every `.adm-page-header h1` in the CRM, which is the intent; check a couple. Verify by COMPUTED STYLE.

- **Reprints print today's persona name — that is right; say so, and mark suspended recipients in bulk**
  - Now: `ork_awards` stores no persona (checked every column) and there is no persona-history table, so `scroll_for_awards_id()` (`model.Scrollery.php:52-53`) necessarily reads the CURRENT `ork_mundane.persona`. A player who changed their name gets the new one on a reprint of a 2009 award — the inclusive default, and structurally impossible to get wrong. Meanwhile `Scrollery_bulk.tpl:222` prints `$r['Recipient']` plain, while the composer's autocomplete (`scrollery.js:460-464`) already renders `inactive` and `suspended` markers.
  - Proposal: state the naming rule in the `mine` lede (`Scrollery_mine.tpl:64-67`) — *"Certificates print your current persona name"*. In bulk, carry `m.suspended`/`m.active` through `bulkSqlForTest()` and mark those rows with the same chip the autocomplete uses; leave them selected by default (a suspended member's past award is still theirs) but let the officer see it.
  - Effort: S — Risk: the suspended flag is authority-gated elsewhere (Playersearch v2); bulk is already officer-only, so consistent, but confirm against those rules.

**Not findings, for the record:** `prefers-reduced-motion` is genuinely covered (`revised.css:6786` global reset; the bare render surface has no motion). Every decorative layer already carries `alt=""` correctly. The flavour text in `scroll-orders.php` is entirely second-person, so no gendered or plural assumption exists anywhere outside the one `with <pronoun> Nth` phrase at `_text.tpl:64`. `possessive_pronoun()` reaches the right word for all 17 distinct `pronoun_freetext` values across 3,282 real rows, `he/him -> his` included.
